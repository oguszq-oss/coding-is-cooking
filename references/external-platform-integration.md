# 外部平台接入：外卖平台支线

只在解释 SDK、第三方或支付平台接入、Webhook、OAuth、回调、签名、平台测试沙箱、限流和接口版本时读取相关章节。它是一条按需支线，不把所有软件概念都改写成外卖剧情。

作答只取用户所问的最小闭环：先下结论，再串必要因果，最后补一条边界。只问 SDK 时通常 2—4 句，不照抄整张表，也不把每种可选组件逐项报菜名。

## 核心角色与边界

| 技术概念       | 餐厅画面                             | 不能丢的技术边界                                                                                               |
| -------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 自己的应用     | 要接外部生意的餐厅                   | 应用仍负责自己的业务规则、配置、权限和错误处置                                                                 |
| 第三方服务     | 外卖平台或外部供应商                 | 它是实际提供能力的线上服务，不是 SDK                                                                           |
| API            | 平台的接单通道与单据规矩             | 包含地址、操作、输入、输出、鉴权和错误约定，不只是一张“能点什么”的菜单                                       |
| SDK            | 平台官方或生态提供的接入工具包       | 常含客户端代码库、类型、文档、样例或调试工具；不保证每套都有全部内容                                           |
| 客户端库       | 工具包里直接办接入的现成工具         | 常负责封装 API 调用，可能是 SDK 的主体；SDK 通常还可含文档、样例或其他工具，产品命名也可能混用                 |
| 凭据与签名     | 商户身份牌与盖章规矩                 | 凭据由接入方配置并安全保管；SDK 可按契约带上认证材料或协助签名                                                 |
| OAuth          | 店老板给代办方的限权委托             | 解决有限授权；不等于 SDK，也不能把 OAuth 本身说成登录身份协议                                                  |
| 平台测试沙箱   | 不接真实客单的样板店                 | 是第三方提供的非生产测试环境；不等于限制本机文件、网络和进程能力的 Agent / 执行沙箱，测试通过也不代表正式环境已配置正确 |
| Webhook / 回调 | 平台调度员按登记的收单电话主动报新单 | 技术上是第三方服务向回调地址发请求；接收方要验签、做幂等，并识别或按规则处理乱序；发送方是否重试以平台契约为准 |
| 限流           | 平台规定一段时间最多接多少单         | 是容量与公平规则，不是认证；超限后的等待、重试或拒绝以具体平台为准                                             |

用户明确给出平台名时可以沿用；否则说“外卖平台”或“第三方服务”，不主动替真实品牌补产品规则。

## SDK 与 API 怎样接力

按一条线说清，不把工具包写成会自己营业的服务：

1. 应用调用 SDK 里现成的方法。
2. SDK 按 API 契约，把应用提供或配置的认证材料与业务参数组装成请求并发出。
3. 第三方服务处理请求，返回数据、状态或错误。
4. SDK 帮忙解析回话，应用再决定展示、重试、记账或报错。

Webhook 走相反的发起方向：第三方服务先向应用登记的回调地址发请求。它不是 SDK 在后台一直轮询；平台若重投，应用须能识别重复事件。

支付回调至少闭合“验签 → 幂等 → 核实结果 → 更新订单”；SDK 可辅助，不替应用决定业务状态。

## 三条防混闸

- **SDK 不是平台本身**：装好工具包，不等于账号、权限、网络、服务可用性和业务接入都已完成。
- **骑手不属于 SDK**：骑手与配送对应平台的实际业务履约；SDK 只帮助软件接入，不能说成“外卖平台 + 骑手服务”。
- **SDK 不是必需层**：没有 SDK 也可能直接按 API 契约发请求；有 SDK 只是少写重复的连接代码。社区 SDK 还要另查维护状态与可信度。

外卖平台画面最适合支付、云服务、开放平台等第三方接入。操作系统、硬件或图形 SDK 若套外卖反而绕，先明说“店里没有完全对应”，再退回“设备或平台供应方给的一整套开发工具”。

## SDK 的短答模板

SDK（软件开发工具包）像外卖平台交给餐厅的一套接入工具：把 API 的通道规矩封装成现成代码和说明，省去反复拼单。API 仍是双方办事的契约，平台才提供服务，骑手只管实际履约；SDK 不替它们营业，也不替应用负责账号、权限和业务处置。
