# coding-is-cooking-zhongcan（中餐厅类比沟通法）

一个 Kimi Code / Claude Code 风格的 Skill：让 AI 在 vibe coding 全程用**经营中餐厅**的类比，向没有编程背景的餐饮从业者解释一切技术概念——前厅是前端，后厨是后端，冷库仓库是数据库，传菜窗口是 API。

目标不是教会写代码，而是"听懂"：知道某个术语在编程场景里是做什么的，能对 AI 的活儿有判断力。

## 三个档位

| 档位         | 说法                                             | 适合                     |
| ------------ | ------------------------------------------------ | ------------------------ |
| 1 档（默认） | 类比为主，术语首次出现带括号原文："后厨（后端）" | 想边用边学术语           |
| 2 档         | 纯类比，一个术语都不出现，3~5 句话对话体         | 一个字的术语都不想看见   |
| 3 档         | 先给技术内容（最多三行），再附"用店里的话说"翻译 | 想逐步过渡到能读技术内容 |

对话中直接说"换 2 档"即可切换，AI 不会多嘴确认，直接用新档位说话。

## 输出示例

**解释 CORS 报错（1 档）：**

> 不严重，你什么都不用做，这活儿是我的。
>
> 你点"下单"，是前厅（前端）把单子递去后厨（后端）。卡壳的地方在后厨师傅还不认识前厅的人，生面孔递单，他按规矩不收——这就是那个 CORS 报错。单子根本没进厨房，所以按钮看着像没反应。
>
> 修法是我去后厨的规矩（后端配置）里添一句：前厅是自己人，递的单照收。改完我叫你，你再点一次试试。

**解释数据库和 migration（2 档）：**

> 你说的这两件事是一套的。头一件是给店里立本账：现在客人点的单只存在点单页面上，页面一关就没了；立了账本，每单都记上，本子收进柜子，哪天要查都翻得到。
>
> 第二件是你说的那个 migration，是改账本格式的规矩：账本的栏目不能随手改，每改一次先开张单子，写清改哪栏、照单改、单子存底，改错了照单子退回去。

## 为什么这么难（本 skill 解决什么）

让 AI 打比方容易，打**对**比方极难。本 skill 的规则全部来自真实用户六轮以上的迭代反馈：

- **类比要在真实餐厅世界里成立**：一家店不会有两个门牌号；纸不能冻进冷库；冷库放食材、账本记订单，空间和物件不混。
- **整段要有连续因果**：上一步的结果必须成为下一步的依据，不能靠“然后”把点单、出菜、收桌等不同环节硬拼起来。
- **物流方向铁律**：单子只从前厅流向后厨，后厨回的是菜和回话——"前厅在等后厨的单子"是病句。
- **落到人**：让厨师、服务员做动作，不让"前厅"和"后厨"两个抽象区域打架。
- **先过人话检查**：去掉术语后，店里的人仍然会这样说；没有自然对应的技术标签直接保留，不硬造餐具或单据。
- **空 ≠ 没有**：空列表不报错，undefined 才报错——"单子上没写字"和"纸还没到手上"是两回事。
- **简练是理解的前提**：直接给结论，无"先给你结论"式元话语，无换档确认寒暄。
- **去 AI 味**：破折号成瘾、三段排比、填充过渡、安抚堆叠、拔高收尾，检出即删；许可半文半白短句。

## 安装

把 `coding-is-cooking-zhongcan/` 整个文件夹放到项目的 `.kimi-code/skills/` 下（Claude Code 用户放 `~/.claude/skills/`），重启或重新加载 skills 即可。

```
coding-is-cooking-zhongcan/
```
